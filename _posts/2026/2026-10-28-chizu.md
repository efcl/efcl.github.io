macOSの既定のブラウザとして登録しておき、開いたリンクを設定ファイルのルールに応じて、指定したブラウザとプロファイルへ振り分けるアプリ [Chizu 🧀](https://github.com/azu/chizu) を作りました。

- GitHub: [azu/chizu](https://github.com/azu/chizu)

Chizuには、ブラウザを選ぶ画面や設定画面はありません。
振り分けのルールは`~/.config/chizu/config.jsonc`というJSONCファイルに書き、リンクを開くたびにこのファイルを読み直します。
行き先のブラウザには、[Dia](https://www.diabrowser.com/)とGoogle Chromeであれば、プロファイルも指定できます。

## インストール

動作環境は次のとおりです。

- Apple SiliconのMac + macOS 14以降

次のコマンドでインストールし、ChizuをmacOSの既定のブラウザに設定できます。
いつも通りnotarizationはしてないので、自己判断でご自由にどうぞ。

```sh
curl -fL https://github.com/azu/chizu/releases/latest/download/chizu-macos-arm64.zip -o "$TMPDIR/chizu-macos-arm64.zip" &&
curl -fL https://github.com/azu/chizu/releases/latest/download/chizu-macos-arm64.zip.sha256 -o "$TMPDIR/chizu-macos-arm64.zip.sha256" &&
(cd "$TMPDIR" && shasum -a 256 -c chizu-macos-arm64.zip.sha256) &&
mkdir -p "$HOME/Applications" &&
ditto -x -k "$TMPDIR/chizu-macos-arm64.zip" "$HOME/Applications" &&
xattr -dr com.apple.quarantine "$HOME/Applications/Chizu.app" &&
/System/Library/Frameworks/CoreServices.framework/Frameworks/LaunchServices.framework/Support/lsregister -f "$HOME/Applications/Chizu.app" &&
"$HOME/Applications/Chizu.app/Contents/MacOS/chizu" default set
```

ダウンロードしたZIPは、一緒に公開しているSHA-256のチェックサムと照合してから展開しています。
アプリはバージョン間で同じ自己署名の証明書で署名していて、Appleの公証（notarization）はしていないため、`xattr`でquarantine属性を解除しています。

## なぜ作ったか

これまでは、リンクをURLやリンク元のアプリに応じて振り分けるmacOSアプリの[Choosy](https://choosy.app/)を使っていました。
Choosyには、URLやリンク元のアプリを条件にした[ルール](https://choosy.app/help/settings/rules)を設定できます。

Chizuを作った主な理由は2つあります。

1つ目は、ChoosyがDiaのプロファイル指定に対応していなかったことです。
Diaは、Arcを作ったThe Browser Companyによるブラウザです。
ChoosyからDiaでリンクを開くことはできますが、プロファイルを指定して開くことはできませんでした。

2つ目は、設定を複数のMacで共有したかったことです。
Choosyには、設定を複数の端末で共有する標準的な方法が用意されておらず、plistファイルを扱う形になっていました。
振り分けのルールは普通のファイルとしてGitで管理し、差分を確認しながら複数のMacで同期したいと考えていました。

そこで、設定ファイルでルールを管理でき、DiaとChromeのプロファイルまで指定できる既定のブラウザとしてChizuを作りました。
設定ファイルはシンボリックリンクでも読めるので、dotfilesのリポジトリでGit管理できます。

## 仕組み

Chizu自体はWebページを表示しません。
ChizuをmacOSの既定のブラウザとして登録しておき、リンクを受け取ったら設定ファイルのルールで行き先を決めて、実際のブラウザで開きます。

処理の流れは次のとおりです。

1. macOSが、他のアプリで開いたリンクを既定のブラウザであるChizuへ渡す
2. Chizuが設定ファイルを読み込んで検証する
3. 上から順にルールを評価し、最初に一致したルールの行き先を決める
4. 行き先のブラウザでURLを開く（プロファイルの指定があれば、そのプロファイルで開く）

詳しい仕組みは、Chizuの[リンクの振り分けの設計](https://github.com/azu/chizu/blob/main/docs/products/chizu/features/routing/design.ja.md)に書いています。
リンク元のアプリは、macOSから受け取ったApple Eventの送信元から判別できた場合だけ、ルールの条件に使います。

## 設定ファイルの書き方

設定ファイルは、`version`、ルールに一致しなかったときの行き先である`default`、上から順に評価する`rules`の配列で構成されています。
各ルールは`name`、条件を書く`when`、行き先を書く`destination`を持ち、最初に一致したルールの行き先でリンクを開きます。

```jsonc
{
  "version": 1,
  // どのルールにも一致しなかったときの行き先
  "default": { "bundleID": "com.apple.Safari" },
  // 上から順に評価して、最初に一致したルールを使う
  "rules": [
    {
      "name": "Docs in Chrome",
      "when": { "host": "docs.example.com" },
      // Chromeに表示されているプロファイル名を指定する
      "destination": { "bundleID": "com.google.Chrome", "profile": "Work" }
    },
    {
      "name": "Team links",
      // ホストとパスの前方一致の両方を満たすときだけ一致する
      "when": { "host": "team.example.com", "pathPrefix": "/projects" },
      "destination": { "bundleID": "company.thebrowser.dia", "profile": "Team" }
    },
    {
      "name": "Calendar links from Mail",
      // Mailから開いたリンクのときだけ一致する
      "when": { "urlContains": "calendar", "sourceBundleID": "com.apple.mail" },
      "destination": { "bundleID": "com.google.Chrome" }
    },
  ],
}
```

`when`には、次の条件を書けます。
1つの`when`に複数の条件を書いた場合は、すべてを満たしたときだけ一致します。

| `when`の項目 | 一致する条件 |
| --- | --- |
| `urlContains` | URL全体のどこかに文字列を含む（大文字・小文字は区別しない） |
| `urlRegex` | URL全体がICU形式の正規表現に一致する（`(?i)`で大文字・小文字を無視できる） |
| `host` | ホストが完全一致する（大文字・小文字は区別しない） |
| `pathPrefix` | パスが指定した文字列から始まる |
| `sourceBundleID` | リンクを開いたアプリのBundle IDが一致する |

設定ファイルはJSONCなので、`//`や`/* ... */`のコメントと末尾のカンマを書けます。
末尾のカンマは、[JSONCの仕様](https://jsonc.org/)ではパーサーが任意で対応してよい拡張として扱われていて、Chizuはこれを受け付けています。

## 振り分け先を事前に確認できる

Chizuは、ルールの結果を事前に確かめられることを重視しています。
`chizu`コマンドには、設定ファイルの検査と、URLがどこで開くかを確認するサブコマンドがあります。

```sh
# 設定ファイルを作る（既にファイルやシンボリックリンクがある場合は上書きしない）
~/Applications/Chizu.app/Contents/MacOS/chizu config init
# 設定ファイルにエラーがないか検査する
~/Applications/Chizu.app/Contents/MacOS/chizu config check
# リンクを開かずに、一致するルール・ブラウザ・プロファイルを表示する
~/Applications/Chizu.app/Contents/MacOS/chizu check 'https://team.example.com/projects/123'
# Mailから開いた場合を想定して確認する
~/Applications/Chizu.app/Contents/MacOS/chizu check 'https://calendar.example.com/' --source com.apple.mail
```

また、設定ファイルが壊れている場合や、指定したブラウザやプロファイルが見つからない場合はエラーとして報告します。
別のブラウザやプロファイルで黙って開くことはしないので、意図しないアカウントでリンクを開いてしまうことを避けられます。

設定ファイルはリンクを開くたびに読み直すため、設定を変更してもアプリの再起動は不要です。

### AIに設定してもらう

`chizu --help`には、コマンドの書式に加えて、設定ファイルの項目や評価の順序、コピーして使える例を表示しています。
そのため、READMEには、AIエージェントに渡して設定してもらうためのプロンプトも載せています。

- [Configure with an AI](https://github.com/azu/chizu#configure-with-an-ai)

このプロンプトの末尾に「GitHubのリンクは仕事用のChromeのプロファイルで開く」のような振り分けの希望を書いて、AIエージェントに渡します。
すると、AIエージェントが`config check`や`check URL`で確認しながら設定ファイルを作ってくれる想定です。

## DiaとChromeのプロファイルを指定する

`destination`の`profile`には、ブラウザに表示されているプロファイル名を指定します。
プロファイルを指定できるのは、Dia（`company.thebrowser.dia`）とGoogle Chrome（`com.google.Chrome`）です。

Diaのプロファイル指定には、Diaが提供しているAppleScriptの機能を使っています。
指定したプロファイルに新しいタブを作り、そのタブを選択してからDiaを前面に出します。
初めてDiaへ振り分けるときに、macOSからオートメーションの許可を求められるので、ChizuがDiaを操作することを許可します。

Diaのプロファイルを切り替える方法としては、[Dia Router](https://github.com/jdsimcoe/dia-router)のように、プロファイル切り替えのキーボードショートカットを送る方法もあります。
Chizuでは、ショートカットの設定や切り替えの待ち時間に依存しないように、AppleScriptで操作する方法を選んでいます。

Chromeのプロファイル指定では、まずChromeの`Local State`ファイルから、プロファイル名とディレクトリの対応を読み取ります。
そのディレクトリを`--profile-directory`オプションで指定して、Chromeを起動します。
同じ名前のプロファイルが複数ある場合や見つからない場合は、リンクを開かずにエラーとします。
`Local State`は他のアプリのデータなので、初回はChizuからGoogle Chromeのデータへのアクセスを許可します。
許可はシステム設定 → プライバシーとセキュリティ → ファイルとフォルダから行えます。

## ブラウザ内のリンクも振り分ける

macOSの既定のブラウザを経由するのは、メールやチャットなど、ブラウザ以外のアプリから開いたリンクです。
ブラウザの中で開いたリンクは、そのブラウザ自身が開くため、Chizuには届きません。

そこで、Chizuは`chizu-http:`と`chizu-https:`というURLスキームも登録しています。
ユーザースクリプトやブラウザ拡張で、リンクの`https:`を`chizu-https:`に置き換えて開くと、Chizuが先頭の`chizu-`を取り除いてから、通常のリンクと同じルールで振り分けます。

```sh
# chizu-https: のリンクも同じルールで確認できる
~/Applications/Chizu.app/Contents/MacOS/chizu check 'chizu-https://team.example.com/projects/123'
```

`chizu://open?url=...`のようにURLをクエリパラメーターで渡す方法では、元のURLをエンコードしなければなりません。
スキームだけを置き換える方法なら、エンコードせずに元のURLをそのまま渡せます。

どのリンクをChizuへ渡すかは、ブラウザ側のユーザースクリプトや拡張で決めます。
渡したリンクの行き先が送り元のブラウザだった場合はそのブラウザで開くので、設定ファイルで別のブラウザへ振り分けるリンクだけを渡すようにします。

## まとめ

Chizuは、macOSの既定のブラウザとして、開いたリンクを設定ファイルのルールに応じてブラウザとプロファイルへ振り分けるアプリです。
URLの文字列やホスト、パス、リンク元のアプリを条件にして、DiaとGoogle Chromeのプロファイルまで指定できます。

設定はJSONCファイルなので、dotfilesとしてGit管理して複数のMacで共有できます。
また、`chizu check URL`を使えば、リンクがどこで開くかを事前に確認できます。
プロファイルが見つからないときに別のプロファイルで開くことはしないので、仕事と個人でプロファイルを分けている場合に便利です。

凝った機能があるわけではなく、自分の困りごとを解決するための小さなアプリです。
いつも通りAppleの公証（notarization）はしていないので、ご自由にどうぞ。
